# ADR-0001：Education Compass ¥39.90 原生小程序付费闭环

- 状态：Accepted
- 日期：2026-08-20
- 决策范围：Phoenix Family OS Mini Program MVP V0.1 工作副本

## 背景

现有代码是原生微信小程序演示原型，但身份、家庭、学生、问卷、报告和角色都保存在客户端本地存储。问卷提交后由客户端规则引擎立即生成并展示完整报告，项目没有可信服务端、订单、支付、权益、退款、PDF门禁或真实 OpenID。

九份产品材料存在版本口径差异：较早的30天任务书把原生小程序及商业支付放到后续版本；较新的90天计划把 ¥39.90 报告纳入商业验证，但仍以 H5 为主。当前用户明确要求原生微信小程序内完成微信支付，因此该要求覆盖旧的渠道排期，不改变文档中关于报告、规则、隐私和交易安全的有效约束。

## 决策

### 产品与权益

- 上线 SKU 为 COMPASS_REPORT_SINGLE_39_9，服务端价格固定为3990分、CNY。
- 一笔订单对应一个用户、家庭、学生、不可变测评快照和报告。
- 这是一次性购买，不订阅、不自动续费，不创建或修改 PHOENIX_MEMBER_199 会员权益。
- 支付前只返回白名单预览；支付后凭 ACTIVE entitlement 返回六模块完整报告。
- 报告六模块为成长画像、优势能力、3–5个专业方向、大学与专业匹配、升学路线、6–24个月规划。

### 交付门槛

- 未成年人或年龄未知时必须记录有效监护人同意。
- 6步23字段问卷使用同一版本化JSON合同；服务端拒绝未知/类型错误字段，客户端remote提交前用草稿GET核对已填写字段往返一致。
- 完整度由服务端按该合同计算；低于70不得生成可收费预览或订单。
- 硬规则决定资格、候选集和分档；AI只能解释结构化结论。
- submit时必须在可信后端生成全部六模块、通过事实和安全QA，并以 `qaPassed=true、status=LOCKED、deliveryStatus=LOCKED` 保存。production 只接受有效的 `verified` Source Catalog manifest；placeholder、生成失败或QA失败均不得创单/预支付。

### 运行架构

- 原生小程序继续使用 WXML/WXSS/JavaScript，不用 WebView 替代核心流程。
- 新增可信 server/。默认采用 Node.js + TypeScript；生产交易数据设计为 PostgreSQL 事务存储。
- 本地演示适配器只用于开发；生产构建必须使用远程服务。客户端本地 ID、金额、角色和订单状态都不可信。
- 飞书可以接收脱敏运营镜像，但不作为订单、支付通知或权益事实源。

### 微信支付

- 服务端用 OpenID 调用微信支付 API v3 JSAPI/小程序下单；客户端只接收调起参数并调用 wx.requestPayment。
- 订单收银台等待阶段使用PENDING主状态。
- 客户端 success/cancel/fail 只触发服务端查单，不直接解锁报告。
- 只有验签解密后的支付通知，或服务端主动查单得到的可信成功状态，才能把订单变为 PAID。
- 通知记录、订单状态、ACTIVE权益、报告DELIVERED状态和一次性交付在同一事务/等价原子边界处理，并用唯一约束保证幂等；付款成功后不再生成或QA报告。
- 真实 provider 与 mock provider 隔离；production 使用 mock、touristappid 或缺少支付配置时必须 fail closed。
- `PAID_COMPASS_ENABLED` 默认 `false`。只有P0审批、生产配置与人工验收留证后才能在受控发布中设为 `true`；关闭时拒绝新的创单和预支付。
- 微信下单携带服务端订单 `time_expire`。`PENDING` 到期先查单；仅当可信查询为 `NOTPAY` 且关单成功后才转 `CANCELLED`，服务端对主动查单至少节流5秒。
- Kill switch 不撤销已发出的签名支付参数，也不丢弃其可信成功结果。开关关闭或当前目录撤回后，在途交易若仍通过签名、金额、商户、AppID和付款OpenID校验，必须完成既有锁定报告的交付；目录异常改走人工事故、退款与审计流程。
- 退款 `SUCCESS` 为单调终态，后到的 `PROCESSING/CLOSED/ABNORMAL` 不得恢复访问或倒退账本；主动查退款可补偿成功通知丢失。

### 数据与隐私

- AppSecret、session_key、商户私钥、API v3密钥、微信支付公钥/平台证书和AI密钥只存在于可信运行环境。
- 小程序不再持久化完整家庭数据库、问卷全文或付费报告。
- 日志和埋点不得包含姓名、手机号、OpenID、开放题全文、报告正文或密钥。
- 报告保留 student、questionnaire、rule、data、prompt、template 版本及 Source ID。
- PDF只通过ACTIVE entitlement鉴权后的临时下载/文件流交付，不暴露永久公开地址。

## 被否决的方案

1. **只在现有报告页前增加支付按钮**：客户端仍持有完整报告和角色，可绕过，且无法可信确认付款。
2. **以 wx.requestPayment success 直接交付**：前端回调不是支付事实源，无法处理回调延迟、查单、重复通知和异常状态。
3. **用 wx storage 或飞书保存交易事实**：缺少可靠事务、并发约束和服务端所有权校验。
4. **用演示院校数据开放真实收费**：违反 Source ID、事实QA和禁止编造的产品边界。
5. **把39.9报告并入199会员**：两份产品材料定义的购买单位和权益不同，会造成重复收费与错误授权。

## 后果

- 家庭、学生、测评、报告和权限必须逐步迁移到服务端；现有同步 repository 不能无侵入替换为网络调用。
- 自动化可以覆盖全部状态机和加密协议边界，但真实扣款仍需要认证 AppID、已绑定商户号、公网 HTTPS 回调、合法域名及真机人工验收。
- 报告访问期限、重新生成、退款后撤权、发票和交易类小程序合规仍需业务/法务确认，记录在 OPEN_DECISIONS.md。
