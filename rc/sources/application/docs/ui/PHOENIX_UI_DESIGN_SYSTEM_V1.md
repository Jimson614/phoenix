# Phoenix UI Design System V1

> 文档状态：实施基线  
> 版本：V1  
> 基线日期：2026-08-26  
> 适用范围：源码注册的 16 个微信原生小程序页面；正式 release 包含其中 14 个家庭端页面  
> 关联文档：[路由状态矩阵](./PHOENIX_UI_ROUTE_STATE_MATRIX_V1.md) · [视觉资产清单](./PHOENIX_UI_ASSET_MANIFEST_V1.md) · [视觉验收报告](./PHOENIX_UI_VISUAL_ACCEPTANCE_REPORT_V1.md)

## 1. 目的与约束

本规范固化当前已经落地的 Phoenix Nova / Education Compass 视觉语言，供后续页面、状态和组件维护使用。它约束视觉呈现，不改变问卷、支付、报告、AI、授权、顾问或 release 构建逻辑。

两张外部参考图仅用于提炼风格。参考图中的价格、语言切换、分享入口、状态栏、左右并排手机和示例文案均不自动成为产品需求。业务文案、价格、权限、支付状态和 AI 安全边界始终以当前代码及服务端数据为准。

规范关键词：

- **MUST**：新增或修改 UI 时必须满足。
- **SHOULD**：无明确技术阻碍时应满足。
- **MAY**：在不破坏一致性和业务边界时可选。
- 当前实现与本文冲突时，应先确认是否为有意变更；不得静默修改业务逻辑来迁就视觉稿。

## 2. 视觉原则

1. **温暖但克制**：暖象牙白为大面积底色，深海军蓝承载信息，香槟金只用于品牌、强调和关键行动。
2. **先建立信任，再推动行动**：隐私、授权、来源、支付和限制说明必须清晰可读，不能被装饰弱化。
3. **衬线负责叙事，无衬线负责操作**：宋体气质用于品牌标题和报告重点；正文、按钮、表单、状态和数据使用系统无衬线。
4. **装饰不参与业务**：羽毛与罗盘为非交互视觉层，不携带状态，不拦截点击，不替代文字标签。
5. **服务端权威**：价格、付款、权益、报告交付和 AI 可用性不得通过纯前端视觉状态自行推断。
6. **原生微信优先**：不使用 WebView 还原设计，不绘制假 iOS 状态栏或假微信胶囊，不依赖外部字体和远程图片。

## 3. 设计 Token

当前全局实现位于 `app.wxss`。页面可以组合 token，但不应再创建含义相同、色值略有差异的新变量。

主按钮渐变：

```css
--gradient-primary: linear-gradient(100deg, #9B6917 0%, #7F4F07 100%);
```

使用规则：

- 小于 28rpx 的金色文字 MUST 使用 `--gold-deep`，不得使用浅金。
- 危险操作 MUST 保留危险色和明确文字，不能统一改成金色。
- 禁止用纯黑、冷白灰、荧光金或高饱和促销红替代本色板。
- 任何新组合都需要重新检查文字与背景对比度；正文目标至少 4.5:1，大号文字至少 3:1。

| Button | 系统无衬线 | 30rpx / 1.2 | 650 字重 |
| Caption | 系统无衬线 | 21–23rpx | 状态、日期、来源细节 |

系统正文字体栈：

```css
-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif
```

规则：

- 正文、选项、表单、价格、状态和按钮 MUST 使用无衬线。
- 宋体仅用于叙事性标题和报告重点，禁止整页正文宋体化。
- 品牌 Logo MUST 使用批准的本地 Logo 资产或 `brand-mark` 组件，不得临时用普通文字拼写。
- 不引入 `@font-face`、远程字体或 CDN 字体。

## 4. 页面背景与装饰

标准页面背景由暖纸色线性渐变和低透明径向金色光晕构成。装饰资产见[视觉资产清单](./PHOENIX_UI_ASSET_MANIFEST_V1.md)。

### 4.1 羽毛

- 使用 `/assets/ui/feather-champagne.png`。
- SHOULD 放在右上、左下或页面边缘，页面内通常不超过两个焦点。
- 推荐透明度 0.12–0.30；内容密集页面 SHOULD 更低。
- MUST 设置为非交互层，例如 `pointer-events: none`，并置于正文下方。
- 不得穿过正文、输入框、支付按钮、同意复选框或危险操作。
- 同一羽毛资产可以旋转或裁切复用，不应为每页复制一份位图。

### 4.2 罗盘

- 使用 `/assets/ui/compass-champagne.png`。
- 普通状态和页头建议 102–144rpx；落地页主视觉可放大。
- 罗盘只表达 Phoenix / Education Compass 品牌语义，不表达支付成功、AI 完成或医学诊断。
- 不使用 emoji 替代主罗盘资产。
- 禁止持续旋转；如使用过渡，只允许短时淡入或轻微缩放。

## 5. 核心组件

### 5.1 面板 `.panel`

- 暖白半透明表面、1rpx 暖色边框、28rpx 圆角和轻阴影。
- 默认内边距 32rpx，≤360px 时 28rpx。
- `.panel--navy` 仅用于高价值品牌区，不用于大段正文。
- `.panel--gold` 用于选中、提示或升级区域，不用于错误。

### 5.2 按钮

- `.btn--primary` 与 `.btn--gold`：深金渐变、白字、CTA 阴影。
- `.btn--outline`：暖白半透明底、深金描边和文字。
- `.btn--text`：无底色，至少 88rpx 高。
- 按下态为约 `scale(.985)` 的 180ms 反馈。
- 禁用态 MUST 使用 `[disabled]`，浅米灰背景、无阴影、清晰文字；不能只降低到不可读透明度。
- `loading` 状态 MUST 保持按钮宽度稳定，并防止重复提交；是否禁用由原业务逻辑决定，视觉层不得擅自改变。
- 撤回和删除 MUST 保留危险色与明确动词。

### 5.3 表单

- 输入、文本域和 picker 使用暖白背景、1rpx 暖边、20rpx 圆角。
- 输入高度 96rpx；文本域最小高度 196rpx。
- 聚焦态为品牌金边和低透明外环。
- 必填标记使用危险色。
- 标签与输入之间保持 14rpx；字段之间通常为 30rpx。
- 长文案 MUST 自然换行，禁止固定文字高度或省略关键授权内容。

### 5.4 状态、标签与来源

- `.status` 使用克制绿色表达有效或完成；`.status--warm` 使用浅金表达中性进度。
- 可信来源显示 MUST 保留来源别名、名称和可用细节，不能为视觉简化而删除。
- 评级、付款、进度和授权不能只靠颜色表达，必须同时有文字。
- Guardian attention、错误、撤回、删除采用危险语义，不与普通金色提示混用。

### 5.5 问卷

- 顶部必须展示测试类型、当前题/总题数和服务端草稿/进度状态。
- 选项整行可点击，左侧统一图标、中央文字、右侧选择状态。
- 选中状态同时使用边框、底色和选择标记，不能只改变颜色。
- 保存、提交、题库切换期间的禁用和 loading 状态不得删除。
- Sticky/fixed 底部操作区 MUST 给内容预留空间并避开安全区。

### 5.6 报告与 AI

- 报告、免费分析、已购报告分析和已购追问是不同内容层级，视觉上可同源但不得合并业务入口。
- 报告来源、版本、免责声明、限制、监护人提示和 AI 双重同意 MUST 保留。
- AI 空态、运行、有限轮询、失败、BLOCKED、同意失效、撤回和删除均需有独立可读状态。
- 支付前不得用模糊、遮罩或假正文暗示已生成的完整结果；锁定页只能展示服务端允许的目录和商品信息。

## 6. 状态语法

所有拥有对应业务状态的页面 SHOULD 使用以下顺序：

1. **Loading**：骨架或居中状态；明确“正在读取/核验/保存”。
2. **Error / Blocked**：可读错误说明和真实恢复操作；不得伪造成功内容。
3. **Empty / Onboarding**：解释为什么为空并提供真实下一步。
4. **Content**：正常内容。
5. **Disabled / Busy**：按钮、输入或敏感动作在业务处理中不可重复触发。
6. **Success**：仅在服务端或既有业务逻辑确认后展示。

各路由实际覆盖见[路由状态矩阵](./PHOENIX_UI_ROUTE_STATE_MATRIX_V1.md)。矩阵中“未实现独立状态”表示当前代码事实，不授权视觉层自行添加网络逻辑。

## 7. 响应式规则

- 以 rpx 为主要布局单位，边框可使用 1rpx。
- 320、360、375、390、430 宽度均需手工检查；步骤见[视觉验收报告](./PHOENIX_UI_VISUAL_ACCEPTANCE_REPORT_V1.md)。
- ≤360px 时全局 gutter 降为 32rpx，H1/H2 和卡片内边距同步收紧。
- 不把参考图中的两台手机做成移动端左右双栏。
- 四列维度、双按钮和双列表单在空间不足、文案变长或字体放大时 MUST 降为两列或纵向堆叠。
- 页面不得产生水平滚动；装饰可以越界裁切，但正文和按钮不可以。
- 固定/粘性操作区必须考虑 `env(safe-area-inset-bottom)`。

## 8. 微信原生与可访问性

- 自定义导航页 MUST 使用实际状态栏高度和 `wx.getMenuButtonBoundingClientRect()` 结果避让胶囊。
- 不实现参考图中的假 9:41、信号、电池或假微信胶囊。
- 支付、授权和隐私流程继续使用微信原生能力；只优化进入流程前后的说明。
- 图片必须为本地资产；不使用远程 `http(s)` 图片、外部样式或大体积 base64。
- 交互目标最小 88×88rpx；整行选项应可点击。
- 装饰图片使用 `aria-hidden="true"`；有业务含义的图片提供 `aria-label` 或邻近可见文字。
- Loading 区域 SHOULD 使用 `aria-busy="true"`，错误 SHOULD 使用 `role="alert"`，状态 SHOULD 使用 `role="status"`。
- 关键信息不能只通过颜色、位置或动画表达。
- 动效不循环、不闪烁；手工验收时需要检查系统字体放大和减少动态效果场景。

## 9. 业务与安全不可变边界

视觉修改不得：

- 改变价格、问卷题目、答案、计算规则、接口、路由、handler 或 `data-*` 绑定。
- 把客户端支付回调当作已付款证据。
- 在未付款状态展示完整报告、signals、evidence 或六模块正文。
- 合并免费有限分析、已购报告总分析和已购报告多轮追问。
- 删除学生与监护人双重同意、可信来源、AI 限制、监护人警示、撤回或删除入口。
- 添加没有后端或产品支持的语言切换、分享、客服、收藏或营销按钮。
- 把两个 demo admin 页面带入正式 release。
- 修改 server、services、utils、package lockfile 或 release 排除边界来完成纯视觉需求。

## 10. 禁区

- 不把整张参考图切成页面背景。
- 不使用 emoji 代替核心品牌图标。
- 不用羽毛覆盖文字或输入区域。
- 不在所有卡片上叠加渐变、重阴影和玻璃效果。
- 不使用低对比浅金小字。
- 不为“视觉完整”虚构 loading、success、分享或支付功能。
- 不宣称 DevTools、iOS 或 Android 视觉通过，除非已有对应设备、版本、截图和验收记录。
